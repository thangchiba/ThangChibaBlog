## Vì sao mình tự viết framework networking?

NeoSocket bắt đầu từ [Jingi](/project/jingi) và những lần mình thử scene multiplayer. Xuất phát từ web development, mình muốn giữ cách tổ chức quen thuộc của Spring Boot và ASP.NET: handler, service, dependency injection và chỗ rõ ràng cho logic dùng chung.

Bài toán là làm sao dùng cách tổ chức đó trong ứng dụng real-time có state. Ngoài game và metaverse prototype, mình còn dùng framework này cho app chat [Cypher](/project/cypher).

## Connection, packet và middleware

NeoSocket giữ connection state và chuyển packet đến handler. Middleware là nơi thêm authentication, authorization và các quy tắc kiểm soát traffic. App vẫn phải thiết kế chính sách của mình; có middleware không tự đồng nghĩa với việc server chống được mọi kiểu tấn công.

Neo-Protocol nhận diện packet bằng số và tên. MessagePack là format serialization mặc định, còn Protobuf cũng được cân nhắc cho trao đổi dữ liệu. Binary serialization và packet batching giúp giảm metadata lặp lại và overhead khi gửi. Mức tiết kiệm phụ thuộc payload, nên ước tính 50–90% trước đây không phải kết quả áp dụng cho mọi trường hợp.

Framework hỗ trợ request-response và command một chiều. Mình muốn chọn cách giao tiếp phù hợp với từng thao tác, thay vì lúc nào cũng chờ response.

## Handler và service

Handler chuyển logic của ứng dụng sang service. Ví dụ dưới đây là cấu trúc của một chat handler:

```csharp
[NeoHandler]
public class ChatHandler
{
    [Autowired] private ChatService _chatService { get; set; }
    [HandleMethod]
    public void HandleChat(MessageDTO packet)
    {
        _chatService.HandleChat(packet);
    }
}
```

Service có thể lấy context của connection, gửi tin vào phòng và lưu lại:

```csharp
[Service]
public class ChatService
{
    [Autowired] private IHandleContext _context { get; set; }
    [Autowired] private IChatDB _chatDB { get; set; }
    [Autowired] private ChatManager _chatManager { get; set; }

    public void HandleChat(MessageDTO message)
    {
        //Send message to all user in chatroom
        var chatRoom = _chatManager.GetUser(_context.Sender.State.IdentityId).ChatRoom;
        chatRoom.HandleChat(message);

        //Save message to database
        _chatDB.AddMessage(new MessageEntity
        {
            MessageId = Guid.NewGuid().ToString(),
            RoomName = chatRoom.RoomName,
            UserName = message.UserName,
            Content = message.Content,
            CreatedAt = DateTime.Now
        });
    }
}
```

Mô hình handler hướng tới việc dùng chung cho TCP, UDP, WebSocket, HTTP và Unix socket, dù mỗi transport vẫn có đặc điểm riêng.

## Định nghĩa packet và client

Packet có ID và tên, còn MessagePack key xác định các field:

```csharp
[NeoPacket]
public class MessageDTO : NeoPacket
{
    [Key(0)] public string UserName { get; set; }

    [Key(1)] public string Content { get; set; }

    [Key(2)] public DateTime CreatedAt { get; set; }
}
```

TypeScript SDK có định nghĩa tương ứng để dùng ở web client:

```typescript
@DNeoPacket(0, 'MessageDTO')
export class MessageDTO extends NeoPacket {
  @DKey(0)
  public UserName: string = '';
  @DKey(1)
  public Content: string = '';
  @DKey(2)
  public CreatedAt: Date = new Date();
}
```

Phía server bắt đầu với .NET 7, còn client Unity dùng .NET Standard 2.0. TypeScript SDK cho phép web app dùng cùng cách giao tiếp theo packet. Stateful connection phù hợp với các bài toán này, nhưng không phải website nào cũng cần nó.

## Service lifetime

IoC container có Scoped, Transient, Singleton và Parasitic lifetime đi theo NeoClient. Qualifier giúp chọn implementation khi có nhiều lựa chọn.

```csharp
[Service]
[Scope(ServiceLifeTime.Parasitic)]
public class ConnectService : IConnectService
{
    [Autowired] private ChatManager _chatManager { get; set; }
    [Autowired] private IHandleContext _context { get; set; }
    [Autowired] private IChatDB _chatDB { get; set; }
}
```

NeoSocket có thể chạy như console application hoặc background service trong ứng dụng .NET.

## Những phần còn muốn cải thiện

Dự án có middleware metric cho Prometheus và Grafana; mình cũng đã bắt đầu làm dashboard React để theo dõi. Những việc còn lại gồm giảm dùng Singleton chỉ vì tiện, cải thiện concurrency và caching, cùng làm API dễ hiểu hơn.

Qua dự án này mình tìm hiểu sâu hơn về async programming, thread-safe collection, context switching, serialization, reflection và service lifetime. Message queue và distributed game server là các hướng có thể làm tiếp, chưa phải sản phẩm đã hoàn thành.
